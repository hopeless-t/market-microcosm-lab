# ODD addendum — E096 typed Japanese SaaS negative-evidence taxonomy

## Purpose

The lab now contains three materially different Japanese SaaS case families:

- BBD portfolio transition;
- Allied overseas-SaaS deterioration / reporting break / exit;
- Jooto standalone-growth-business exit.

E096 attacks the label:

`FAILED_SAAS = true`

## Mechanism dimensions

The finite reference keeps these dimensions separate:

- KPI sign ambiguity;
- reporting-kernel break;
- exit decision;
- competitive-advantage failure;
- persistent profitability failure;
- runoff transition;
- residual capability value.

The three public case families have distinct fingerprints and every pair differs on multiple mechanism dimensions.

A one-bit failure label collapses all of that structure.

## Consequence

Negative evidence is stored as a typed mechanism vector, not a generic failure flag.

This allows the lab to distinguish an active portfolio transition from a deterioration-linked liquidation path and from a nonzero-traction strategic SaaS shutdown with runoff and residual value.

Promotion:

`japanese-saas-negative-evidence-requires-typed-mechanism-vector-v1`

## Limitation

Three case families are not an exhaustive taxonomy of Japanese SaaS and the current dimensions are binary. The purpose is semantic separation, not prevalence estimation.
